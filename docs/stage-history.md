# 生命周期阶段历史（stage_history）

## 是什么

全市场每只 A 股、每个交易日的生命周期阶段快照，由**通达信前复权日线**计算，严格只用当日及以前的 bar（无未来数据）。

- 数据：`data/derived/datasets/final/stage_history.parquet`
- 清单：`data/derived/datasets/final/stage_history.manifest.json`（行数、日期范围、阈值快照、对拍结果、陈旧源检查）
- 当前版本：12,504,445 行 / 5,408 只 / 2012-04-06 .. 2026-10-29 / 319 MB（zstd）

## 字段

| 字段 | 含义 |
|---|---|
| market / symbol | 市场（sh/sz/bj）与 6 位代码 |
| trading_day | 交易日 `YYYY-MM-DD`（**仅真实成交日**，停牌占位行不入库） |
| region / stage | 区域与阶段（见下） |
| ma5/ma10/ma20/ma60 | 前复权收盘均线（3 位小数） |
| slope20 / slope60 | MA20/MA60 相对 5/10 个 bar 的涨幅（5 位小数） |
| slope20_prev | 5 个 bar 前的 MA20 斜率，用于「刚拐头」判定 |
| bias20 | 收盘对 MA20 乖离率 |
| pos_high_60 / pos_low_60 | 收盘相对 60 日最高/最低的位置 |
| vol_ratio | 当日量 / 前 5 日均量 |
| high_20 / low_20 / high_60 / low_60 | 区间高低点 |

文件**不含前瞻收益**——那是未来信息，只能在评估脚本里临时计算，不允许落进特征文件。

## 阶段定义（v1，阈值未调）

- 下跌区：D1 破位下跌、D2 主跌、D3 下跌中继
- 底部区：B1 底部盘整、B2 探底回升、B3 回踩确认
- 上升区：U1 上升初期、U2 主升、U3 上升中继、U4 加速赶顶
- 顶部区：T1 高位震荡

阈值：`FLAT_SLOPE=0.005`、`BIAS_CLIMAX=0.18`、`VOL_BREAKOUT=1.5`、`MIN_DAYS=60`（见 `app/stage_classify.py`）。

### 13 状态（2026-10-30 第二次修订）

外部审查用 600309 的 243 个交易日指出：旧规则把“趋势中的回抽/反弹”系统性误判成底部/顶部。全库实测确认（不是个例）：

| 旧标签 | 实测问题 | 处理 |
|---|---|---|
| B2 探底回升 | 82.4% 位于 60 日区间上半、68.7% 距高点不足 10%、25.9% 区间位置 >90% | 加位置门（区间下半或距高点 ≥10%）+ 仅在底部区/下跌区产生 + **不再改写区域** |
| B3 回踩确认 | 66.6% 的 MA60 斜率已 < −0.5%，31.7% < −2%（旧规则只有 ≤ +0.5% 的上限） | 加下限 `slope60 ≥ −0.5%`、`range_pos ≤ 0.5` + 不再改写区域 |
| B1 底部盘整 | 86.9% 的 MA60 斜率 > +0.5%（中期仍上行） | 拆出 **R1 上升回撤** |
| T1 高位震荡 | 75.2% 的 MA60 斜率 < −0.5%（下跌趋势里的反弹） | 拆出 **R2 下跌反弹** |

新增两个状态：

- **R1 上升回撤**：区域=底部区 且 `slope60 > +0.5%`（MA60 仍上行、收盘跌破 MA60、区间下半）。含义是“中期趋势未破坏的深度回调”，不是筑底。
- **R2 下跌反弹**：区域=顶部区 且 `slope60 < −0.5%`（MA60 仍下行、收盘回到其上方、距高点 ≤10%）。含义是“下跌趋势里的反弹”，不是高位横盘。

B1 与 T1 因此收窄为真正的走平筑底 / 走平顶部（MA60 斜率在 ±0.5% 内）。

### P1 修正（同日完成）

- **B3 加回踩深度门**：`bias20 ≥ −8%`。跌破 MA20 超过 8% 属深度回撤，交回 R1（B3 从 121.0 万行降到 88.8 万行）
- **U1 改为「当日首次收复 MA60」**：前一日收盘 ≤ 前一日 MA60、当日站上、`|乖离| < 5%`、MA60 不显著下行；判断提前到 U3 之前（U1 从 39.3 万行降到 9.9 万行，乖离 >5% 的占比 63.4% → 0%）
- **D1 优先于 D3**：MA20 刚拐头是无日事件，先于“短期反弹”暴露（D1 42.6 → 48.5 万行；实测两者条件几乎不重叠）
- **D2 严格要求空头排列**：均线纠缠一律归 D3，不再用“主跌”兜底（D2 非空头占比 19.0% → 0.4%，残余为小数保留造成的等号错觉；D2 280.6 → 209.2 万行）

1 日段占比 35.7% → 30.9%（中位段长 2 → 3）；600309 的 243 个交易日从 60 段降到 39 段。

判定顺序现在是：**先定区域（趋势）→ B2/B3 作为事件加标签（不改区域）→ 区域内定阶段 → 底部区按 MA60 斜率分 R1/B1，顶部区按 MA60 斜率分 R2/T1**。

### 区域位置门（2026-10-30 加入）

原实现只用「MA60 斜率 + 收盘在 MA60 哪一侧」定区域，导致价格离 60 日高点 20% 也能叫「底部盘整」、离高点 13% 也能叫「高位震荡」。现加两道结构门（整数阈值，非拟合参数）：

- `BASE_MAX_RANGE_POS = 0.50`：底部区只接受 60 日区间下半部。MA60 仍上行、收盘跌破 MA60 但价格在区间上半 → 判为**上升区**（通常是 U3 上升趋势回抽）。
- `TOP_MAX_DIST_FROM_HIGH = 0.10`：顶部区只接受距 60 日高点 10% 以内。MA60 转下、收盘仍在 MA60 上方但已离高点超过 10% → 判为**下跌区**（通常是 D3 下跌中继/反弹）。

`range_pos_60` 已作为证据字段写入历史库，可直接审计。

### U2 主升门（2026-10-30 加入）

U2 原是上升区的兜底：只要不追顶、不短踩、不刚站上 MA60，就标「主升」。改前 1,981,808 行里有 13.5%（26.7 万行）收盘低于 MA20，25.2% 均线纠缠。

现在 **U2 要求收盘站上 MA20**；不站上的归 **U3 上升中继**（本就是短期回踩的定义）。

改后实测（行数不变）：U2 1,981,808 → 1,714,249（收盘低于 MA20 占比 13.5% → 0.000%），U3 1,494,782 → 1,762,341（+267,559，正好承接）。

改后实测（全库 12,504,445 行不变）：

| 阶段 | 改前 | 改后 | 说明 |
|---|---:|---:|---|
| B1 底部盘整 | 1,310,347 | 1,240,352 | 区间上半的 5.4% 移出（现为 0.000%） |
| T1 高位震荡 | 903,656 | 495,893 | 离高点 >10% 的 47.9% 移出（现为 5.05%） |
| D3 下跌中继 | 1,581,483 | 1,922,184 | 承接原 T1 的主体 |
| D2 主跌 | 2,116,932 | 2,178,164 | 承接部分原 T1 |
| U3 上升中继 | 1,441,653 | 1,494,782 | 承接原 B1 |
| 其余阶段 | — | — | 变化 <1% |

残余 5.05% 的来源：MA60 走平分支（斜率在 ±0.5% 内）仍按「收盘在 60 日区间中位线上/下」分 base/top，不套用 10% 距高点门。这批样本价格在区间上半、距高点 10%–15%，语义上属「区间中上部震荡」。

**决定（2026-10-30）：保持现状，不再收紧。** 理由：位置门已把 47.9% 名不副实的 T1 改判；剩余 5% 若要收紧，必须先回答「归到底部区还是下跌区」——两者都不成立（下限不在区间下半、MA60 也未下行），强推只会引入新的 5% 噪声。因此 T1 的实际含义按「高位或区间中上部震荡」理解，页面与文档沿用现名。

### 事件型阶段 `is_event`（2026-10-30 加入）

B2 探底回升、D1 破位下跌描述的是**当日动作**，不是可停留的状态：

| 阶段 | 行数 | 平均持续 | 中位 | 最长 |
|---|---:|---:|---:|---:|
| B2 探底回升 | 779,511 | 1.51 bar | 1 | 11 |
| D1 破位下跌 | 186,045 | 2.79 bar | 3 | 5 |
| D2 主跌（对照） | 2,178,164 | 6.09 bar | 4 | 78 |
| B3 回踩确认（对照） | 1,680,045 | 5.54 bar | 3 | 41 |

`classify_stage()` 现在返回顶层字段 `is_event`（`app/stage_classify.py` 的 `EVENT_STAGES = {"B2","D1"}`），页面「当前阶段」卡片对这两个状态显示橙色「事件」徽标，title/aria 中写明「只反映当日动作，不宜作为持仓状态」。

历史库**不额外存 is_event 列**：它可由 `stage` 直接推出（`stage in {"B2","D1"}`），避免冗余列与口径漂移。下游若要用作持仓信号，请自行按 `stage` 过滤。

## 个股阶段时间轴（`/api/stage-history-series`）

个股分析页新增「生命周期阶段时间轴」区块，读历史库而不是只看当日一个状态：

- 接口：`GET /api/stage-history-series?symbol=600036&months=12`
- 返回：`rows`（逐日，**升序**，与 K 线接口一致）、`segments`（连续同阶段的段，含起止日与交易日数）、`current`（当前段与已持续天数）、`longest`、`labels`（阶段/区域中文名与事件阶段清单）、`as_of` / `window_start`、`price_basis=tdx_export_qfq`、`lookahead=none`
- 读法：`app/stage_history_store.load_stage_series()`，对 parquet 下推 `symbol` 过滤（实测 0.08s/次，不物化 12.5M 行）
- 页面：色带宽度按停留交易日数分配，颜色按区域（上升绿/底部灰/顶部黄/下跌红），事件段底部橙线，当前段白边；点任一段显示该段末日的区间位置、距高点、MA60 斜率、MA20 乖离、量比，事件段附「不宜作为持仓状态」
- 错误口径：历史库不存在 → 503 `stage_history_missing`；该股无记录 → 404 `not_found`；`months` 非整数 → 400 `invalid_months`

## 日更（数据更新页的 `rebuild_stage_history`）

阶段历史已接入「数据更新」流水线，作为独立步骤 `rebuild_stage_history`：

- 位置：`sync_tdx_qfq_exports` → `build_stock_filter_qfq_daily` → … → `refresh_rps_daily` → **`rebuild_stage_history`** → `rebuild_macd_signals`
- 为什么排在这里：它同时依赖新的前复权日线（阶段取价）与 RPS 交易日（陈旧源比较），两者都在它之前完成
- 独立性：不触发下载，不被其它步骤读取产物，失败可单独重试；`retry_failed=True` 的子集里也包含它
- 运行时：全量重建约 5.3 分钟 / 12.5M 行（5408 只），内置两道闸门（陈旧源阻断 + 30 只 × 3 年逐 bar 对拍）仍会执行
- 陈旧源阻断：若 QFQ 最新 bar 落后于 RPS 交易日，脚本直接非零退出，不写库；此时应先修数据源，而不是重试

日更后如何确认结果：

```bash
python -c "import json;m=json.load(open('data/derived/datasets/final/stage_history.manifest.json'));print(m['built_at'], m['rows'], m['thresholds'])"
```

manifest 的 `thresholds` 会同时记录四个旧刻度常量、两道区域位置门（`BASE_MAX_RANGE_POS`、`TOP_MAX_DIST_FROM_HIGH`）与事件型阶段清单（`EVENT_STAGES`），`source_staleness_check` 与 `parity` 记录两道闸门的实跑结果。也就是说：**新旧两个 parquet 若语义不同，manifest 一定能看出差别**，不会出现「文件不同、溯源相同」。

## 两条实现，必须逐 bar 一致

| 路径 | 用途 | 文件 |
|---|---|---|
| 标量 `classify_stage(df)` | 股票分析页当日快照 | `app/stage_classify.py` |
| 序列 `classify_stage_series(df)` | 全市场历史建库 | `app/stage_classify_series.py` |

序列版**必须**沿用标量版的 running-sum 累加顺序。pandas 的 rolling mean 与标量累加在浮点末位不同，而阶段规则里全是 `ma5 > ma10`、`slope60 <= FLAT_SLOPE` 这类等号比较，A 股（尤其北交所）均线相等极常见；换成 pandas 算法后 132,724 个 bar 里有 123 处翻转。

## 闸门（都在脚本内，不靠人记）

1. **陈旧源阻断**：QFQ 最新 bar ≠ RPS 最新交易日 → 直接退出，不写文件
2. **对拍闸门**：随机抽 30 只、近 3 年逐 bar 比对标量与序列实现，任一分歧 → 拒绝写盘
3. **数据质量闸门**：统计脚本若算出非有限的前瞻收益（如 0 价当分母）→ 拒绝写报告
4. **原子落盘**：`.tmp` + `os.replace`

## 停牌占位行（重要）

通达信前复权导出把停牌日写成 0.00 价行。400 只抽样中 13 只有，单只最多 1,158 行。

保留这些行会拉坏 MA20/MA60、60 日高低区间与量比，凭空造出阶段。`prepare_bars()` 在**两条路径**都先剔除，占位日返回 `valid=False` 且不位移后续 bar；全量建库因此剔除 73,508 行。

## 已审计结论（2026-10-30）

**站得住的部分**
- 对拍：132,724 bar，region/stage/evidence 全 0 差异
- 抽检：55 个样本（每阶段 5 只）回算 0 不一致，D 区样本确为空头排列、负斜率、贴近 60 日低位
- 持续性：除 B2/D1 外，自持率 56.6%–83.7%，是阶段而非噪声标签

**标签名大于规则的四处（待定义，未改）**
1. ~~**B1 底部盘整**~~ —— 已由位置门修复：区间上半的 5.4% 改判上升区（U3），B1 现在 100% 位于 60 日区间下半部，中位区间位置 0.29
2. ~~**U2 主升**~~ —— 已由「收盘站上 MA20」门修复：13.5% 的样本改判 U3 上升中继
3. ~~**T1 高位震荡**~~ —— 已由位置门修复：离高点 >10% 的 47.9% 改判下跌区（D3 为主），T1 距高点中位数从 −9.7% 收敛到 −6.6%；残余 5.05% 来自 MA60 走平分支，待定
4. ~~**B2 探底回升 / D1 破位下跌**~~ —— 已加 `is_event` 标记与页面「事件」徽标：中位持续 1 / 3 bar，是当日事件而非可停留阶段；枚举保留不变，历史库不新增冗余列

**阶段与前瞻收益不单调（描述性，非策略）**

全市场 20 日均值（位置门之后的 18:57 报告）：D1 +3.21%、D2 +3.07%、D3 +2.44% 最高；B2 +0.92%、U3 +0.66%、B3 +0.52% 最低。20 日中位数：U4 −3.50%、U3 −1.52%、U2 −1.15%，而 D2 +1.22%。

说明：分类器在下跌发生后标「主跌」，天然吃均值回复；U4 均值正而中位大负，是右尾极厚（连板结构）。该表仅证明标签描述价格结构，**不能**当收益排序或选股依据。

## 已知边界

- 样本为当前在市股票，存在幸存者偏差；QFQ 导出不含已退市标的
- 重叠样本，未扣费税滑点，不能相加
- 持续天数以 bar 计，跨停牌日是连续行但仍算一次转换
- 阶段为当日快照，不是预测
